## What is FVS?

A **Feedback Vertex Set** of a graph G is a set of vertices S such that removing S from G leaves a forest (an acyclic graph). Finding the **minimum** FVS is NP-Hard for both undirected and directed graphs.

- **Undirected FVS**: Remove vertices to destroy all simple cycles.
- **Directed FVS (DFVS)**: Remove vertices to destroy all directed cycles (make the graph a DAG).

## File-by-File Reference

### `cpp_engine/include/graph_base.h`

Abstract base class for all graphs. Implements **virtual deletion** via an `active[]` boolean array. Marking `active[v] = false` is O(1) and allows O(1) backtracking in the BST solver — no copying needed for the active flag alone.

### `cpp_engine/include/undirected_fvs.h`

Undirected graph using `std::set<int>` adjacency. Declares the three solver functions exposed to Python. Key operations: `deactivate_full(v)` removes v and all its edges in O(deg(v) log n); `find_cycle()` returns a cycle using DFS with ancestor tracking.

### `cpp_engine/include/directed_fvs.h`

Directed graph with separate `in_adj[]` and `out_adj[]`. Declares directed solvers. Contains `find_SCCs()` — Tarjan's algorithm in O(n + m).

### `cpp_engine/src/core/graph_undirected.cpp`

Implements `UndirectedGraph`. `has_cycle()` uses iterative DFS with 3-coloring. `find_cycle()` uses a recursive-style DFS (via `std::function`) to extract the actual cycle vertices for branching.

### `cpp_engine/src/core/graph_directed.cpp`

Implements `DirectedGraph`. `find_directed_cycle()` uses 3-coloring DFS and parent tracking. `find_SCCs()` is Tarjan's algorithm with discovery-time (disc) and low-link (low) arrays.

### `cpp_engine/src/undirected_algos/kernelization_u.cpp`

Four reduction rules applied before every BST branch:

- **Rule 0**: Self-loop → force vertex into FVS
- **Rule 1**: Degree 0/1 → delete safely
- **Rule 2**: Degree 2, neighbors not adjacent → bypass vertex
- **Rule 3**: Degree > k → force vertex into FVS

### `cpp_engine/src/undirected_algos/exact_solver_u.cpp`

**BST**: Iterative deepening (k=0,1,2,...) + kernelization + cycle-based branching. Sorts cycle vertices by degree for best-first branching.  
**IC**: Greedy initialisation → local search (try removing each vertex) → compression subroutine (enumerate k-subsets).

### `cpp_engine/src/undirected_algos/memetic_u.cpp`

Genetic Algorithm with uniform crossover, bit-flip mutation (p=1/n), tournament selection (size 3), and greedy local search. Representation: binary vector. Fitness: FVS size + n × (1 if infeasible). Repair operator: add high-degree vertices until feasible.

### `cpp_engine/src/directed_algos/kernelization_d.cpp`

Five directed reduction rules:

- **D0**: Self-loop → force into FVS
- **D1**: Source (in=0) or Sink (out=0) → delete
- **D2**: In-degree 1 → bypass (add p→w edges for each successor w)
- **D3**: Out-degree 1 → bypass (symmetric)
- **D4**: SCC decomposition → delete all vertices in trivial SCCs

### `cpp_engine/src/directed_algos/exact_solver_d.cpp`

Same structure as undirected but with directed cycle detection and SCC-decomposed branching. The SCC decomposition enables independent sub-problem solving.

### `cpp_engine/src/directed_algos/memetic_d.cpp`

Same as undirected MA but uses `has_directed_cycle()` and sorts by `min(in_degree, out_degree)` for the repair heuristic.

### `cpp_engine/bindings/pybind_wrapper.cpp`

Registers all 6 solver functions with pybind11. Uses `pybind11/stl.h` for automatic `list[tuple]` ↔ `vector<pair>` conversion. Python keyword arguments (`pop_size`, `max_gens`) are forwarded to C++.

### `experiments/benchmark_undirected.py`

Full CLI with `argparse`. Parses any edge-list file format, auto-detects 1-indexed vs 0-indexed, calls the C++ solver, verifies correctness via Python cycle check, and prints timing results. Supports single file, directory batch, and CSV output.

### `experiments/benchmark_directed.py`

Same as above but for directed graphs. Parses PACE 2022 `.gr` format in addition to generic edge-lists. Verification uses 3-coloring DFS.

### Undirected Algorithms

#### Single algorithm on a single file

```bash
# Bounded Search Tree (exact)
python experiments/benchmark_undirected.py --algo BST --test data/raw_undirected/graph01.txt

# Iterative Compression (exact)
python experiments/benchmark_undirected.py --algo IC --test data/raw_undirected/graph01.txt

# Memetic Algorithm (heuristic)
python experiments/benchmark_undirected.py --algo MA --test data/raw_undirected/graph01.txt
```

#### Memetic Algorithm with custom parameters

```bash
# Larger population, more generations (better quality, slower)
python experiments/benchmark_undirected.py \
    --algo MA \
    --test data/raw_undirected/graph01.txt \
    --pop 100 \
    --gens 500
```

```bash
python experiments/benchmark_undirected.py \
    --algo ALL \
    --test data/raw_undirected/graph01.txt
```

## Graph File Formats

### Undirected Edge-List (`.txt`, `.edges`)

```
# Comments start with # or %
# Format: u v (one edge per line, space-separated)
# Vertices can be 0-indexed or 1-indexed (auto-detected)
0 1
0 2
1 3
2 3
3 4
```

### DIMACS Format (`.dimacs`, `.txt`)

```
c This is a comment
p edge 5 4
1 2
1 3
2 4
3 4
4 5
```

### PACE 2022 Directed Format (`.gr`)

```
c This is a PACE 2022 directed FVS instance
p dfvs 6 8
1 2
2 3
3 1
1 4
4 5
5 6
6 4
2 5
```

> **Note**: PACE format is 1-indexed. The benchmark scripts auto-convert to 0-indexed.

## Algorithm Reference

| Algorithm | Type | Graph | Optimal? | Time Complexity | Best For |
|-----------|------|-------|----------|----------------|----------|
| `BST` | Exact | Undirected | ✅ Yes | O(3^k · n) | Small graphs, k ≤ 20 |
| `IC` | Exact | Undirected | ✅ Yes* | O(k² · n) per step | Medium graphs |
| `MA` | Heuristic | Undirected | ❌ Near-optimal | O(pop · gens · m) | Large graphs |
| `BST` (directed) | Exact | Directed | ✅ Yes | O(3^k · n) | Small digraphs |
| `IC` (directed) | Exact | Directed | ✅ Yes* | O(k² · n) per step | Medium digraphs |
| `MA` (directed) | Heuristic | Directed | ❌ Near-optimal | O(pop · gens · m) | Large digraphs |

*IC returns optimal for most instances; may return near-optimal on very dense graphs where the compression subroutine cannot find a smaller FVS.

### When to use which algorithm

```
Graph size        Recommended algorithm
──────────────    ────────────────────────────────────────────────────────────
n < 50            BST (exact, guaranteed minimum)
50 ≤ n < 500      IC  (fast exact, good for batch benchmarks)
n ≥ 500           MA  (heuristic, typically within 1-5% of optimal)
```

## Troubleshooting

### `ImportError: No module named 'cpp_engine'`

The C++ engine was not compiled, or the build directory was not found.

**Fix:**

```bash
cd cpp_engine
mkdir -p build && cd build
cmake ..
make
# Then verify:
python -c "import sys; sys.path.insert(0,'cpp_engine/build'); import cpp_engine; print('OK')"
```

### BST is very slow

The BST solver has exponential worst-case complexity in k (FVS size). If it's slow:

1. Use `IC` instead — same quality, faster in practice.
2. Use `MA` for large graphs (n > 200).
3. Check if your graph has a large FVS (run `MA` first to estimate).

---

### Verification says `✗ INVALID`

This means the returned FVS does not actually destroy all cycles. Possible causes:

1. **Self-loops in input**: The parser may not handle self-loops. Check your input file.
2. **Duplicate edges**: Some files list each edge twice. The parser deduplicates via `std::set`.
3. **Disconnected components**: Should be handled; if not, file a bug.

To debug, add `--quiet` and check the raw FVS output.

---

### `No graph files found in directory`

The benchmark script looks for files with extensions: `.txt .gr .edges .graph .dimacs .mtx`  
Rename your files to use one of these extensions.

## Common Errors and Fixes

| Error | Cause | Fix |
|-------|-------|-----|
| `ModuleNotFoundError: cpp_engine` | C++ not compiled | `cd cpp_engine/build && cmake .. && make` |
| `ValueError: No edges found` | Empty or wrong-format file | Check file format; must have `u v` pairs |
| BST runs forever | Graph has large FVS (k > 20) | Switch to `--algo IC` or `--algo MA` |
| `Segmentation fault` | Vertex index out of range | Ensure all vertex IDs are within [0, n-1] |
| `torch not found` in dataset_gen | PyTorch not installed | `pip install torch` or ignore (raw .txt saved) |
| `pybind11` cmake error | pybind11 not found by cmake | `pip install pybind11` then re-run cmake |
| Wrong FVS size on PACE files | 1-indexed input not converted | Handled automatically; check parser output |
